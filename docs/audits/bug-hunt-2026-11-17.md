# Bug hunt — 2026-11-17

Scope: everything since the last hunt (`a05e380`, 2026-11-09): 19 commits,
about 1,000 lines of `src/`. Four read-only reviewers, one domain each —
the network (built-in NAT, DNS, W5100 resolver, AI server GET-only), the
audio buffer ladder, slot composition + the bus /NMI + E-Z Color, and the
host-file surfaces (native pickers, file associations, host-folder eject).
Every finding below was re-read in the code before it was acted on.

## Fixed

| Area | Finding | Pin |
|---|---|---|
| Snapshot / rewind / session | The CPU's /NMI edge latch was neither saved nor cleared on restore. /NMI is edge-triggered and the E-Z Color's VDP holds /INT low until the guest reads its status: a capture taken between the edge and its service came back with no NMI pending and no further edge possible — an NMI-driven program froze until RESET. The reverse case replayed a live pending NMI into a restored timeline that never raised it. Now an optional 1-byte `NMI` section, written only while an edge is pending (the usual capture is byte-identical, older readers skip it), applied after the section loop; absent clears the latch. | `rewind_roundtrip` (7), both the rewind and the transactional file path |
| Native pickers | `nativeFileDialogAvailable()` re-scanned PATH and the usual homes for zenity/kdialog on every call, and the panels call it every frame (twice per SmartPort unit row): hundreds of `stat` per frame on the UI thread where zenity is absent, stalls on an NFS `$HOME`. Cached once per process; a helper removed later still fails cleanly at the click. | — (no seam; `native_file_dialog` still covers the protocol) |
| Native pickers | A Save answer with no extension was used as typed: "page1" in Save sheet as PNG / printer PDF / Save tape wrote a file with no extension (a tape silently as ACI). Windows now sets `lpstrDefExt`, zenity/kdialog get `withDefaultExtension` (AppKit already did it). | `native_file_dialog` (pure checks, run before the desktop skip) |
| File associations | `.nb2` is loaded, offered in the Disk II picker and in `--help`, but none of the three association lists (Windows `FileAssociations.ps1`, macOS `Info.plist.in`, Linux `pom2-disk.xml`) named it. | `windows_file_associations_test.ps1` |
| NAT | A guest IPv6 datagram to `::ffff:10.0.2.3:53` routed to DNS through the mapped-address fence, but the answer left through `udpToGuest(kDnsIp, …)` as an IPv4 frame the guest's IPv6 socket never saw, keyed in the IPv4 proxy's dedupe. Now served by the IPv6 DNS path, answering from the address asked (`kDnsMapped6`). The same for a UDP forward's guest port sending over IPv6 to a mapped peer: it went out of the forward's IPv4 socket and came back as IPv4; it now takes the relay, which answers through the alias. Crossed no fence; only a raw IPv6 stack (Uthernet I) emits a mapped address on the wire. | `builtin_nat` [14] |
| Audio ladder | `poll` raised `learned_` before the device had re-opened at the new rung: a rung that failed to open was still remembered and tried at every launch. `poll` now only proposes; `reached()` records it once `reconfigurePeriod` succeeded (pre-existing, not from the refactor). | `audio_buffer_ladder` |
| Audio ladder | `restartWindow(lateNow)` stored a baseline the next `poll` overwrote, so it was `forgetWindow()` under another name, and `restartedWindowForgetsTheOldDevice` passed for a reason other than the one it stated. No behaviour change: one `restartWindow()`, `pin` without the unused counter, the test now pins what happens (the window opens at the first poll after a re-open). A stale comment in `AudioCoordinator::restore` corrected. | `audio_buffer_ladder` |
