### Fixed

| Area | Finding | Pin |

| Zip (browser) | Every central-directory and local-header bound was `off + 46 > n`. The offsets are file-supplied uint32; on wasm32 (32-bit `size_t`) `0xFFFFFFF0 + 46` wraps, the check passes and the read lands 16 bytes before the buffer — reproduced under ASan in node, reachable by dropping a `.zip` on the browser build (media and ROM import). | 6522 cards | A warm RESET re-anchored the lazy sync on `getCycleCountNow()`, which between instructions still counts the last one (the correction `advanceCycles` applies). | Super Serial Card | The restored IRQ line was only re-driven at the next `advanceCycles`, after an instruction — `M6502::step` samples the line before one, so the first instruction after a rewind or session load saw the live card's IRQ. ### Decided, not changed

- **6522 `t1Pb7` and `latchA` are not in the Mockingboard / Phasor blobs.**
  A guest reading ORB bit 7 with ACR.7 set (or ORA with ACR.0) sees a PB7
  phase that a rewind can invert, and continuous T1 never corrects it.
  Widening the 25-byte VIA layout changes MBS3 / PHS3, which the session
  loader replays canonically: every saved session with a Mockingboard or a
  Phasor would be refused. The comment in `Via6522.h` that said both were
  "re-derived within one T1 period" was wrong and now says why they are out.
  Settling it needs a decision on session compatibility (accept MBS3/PHS3
  and write MBS4/PHS4, relaxing the canonical replay for the old ones).
