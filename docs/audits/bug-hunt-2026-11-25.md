# Bug hunt — 2026-11-25 (before v1.2.4)

Four independent reviewers over everything since v1.2.3 (`v1.2.3..63005480`):
the libretro core's disk storage and content access, the core at run time,
the desktop fixes of 651d6dfe, and the build / CI / release text. They
changed nothing and built nothing; each finding below was checked against
the code before it was fixed. The affected tests were rebuilt and run
(`libretro_disk_storage`, `libretro_pad_profiles`, `drive_rack_mount`, the
seven `pom2_libretro_*` package tests including netplay).

## Round 1 — fixed

### Libretro disk storage and content (pass 1)

| # | Finding | Fix | Pinned / checked by |

## Round 1 — not fixed, and why

- **A pad profile in netplay is found from each player's FILE NAME** (pass 2):
  a `.dsk` named differently on the two machines gives one player the
  profile and not the other. Documented in the libretro README's Netplay
  section (same file name, or profiles Off). Keying profiles on image hashes
  needs a hash table per profile.
- **Save states from builds before libretro v1.2.3** (dev builds only; the
  v1.2.2 draft was never released) name a writable disk by its old hex copy
  path and no longer load.
- **The web build aborts on a thrown exception** (RetroArch's web build
  disables catching): `openDiskStorage`'s refusals (a missing copy on a
  restore, an image over 33 MiB) end the page. Pre-existing; the common path
  (the `link()` publish) was fixed on 2026-11-25.
- Cosmetic: the bug report's "mode N" display field; the tape wind ramp
  restarting after a UI stall.
