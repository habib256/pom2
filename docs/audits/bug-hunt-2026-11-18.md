# Bug hunt — 2026-11-18

Four read-only reviewers, none of them building, on four domains the hunts
of 2026-11-17 had not reached: cards that draw a picture whose geometry the
guest controls (Videoterm, UltraTerm, VidHD, E-Z Color, Le Chat Mauve), the
sound sources other than the AY and the 6522 (speech chips, DACs, cassette,
speaker), the printing stack with the guest's byte stream as hostile input,
and the host code that interprets guest memory or user text (debugger,
OS-call trace, BASIC listings, corpus, disk builder). Every finding below
was re-read in the code before it was acted on.

No memory-safety defect came back from any of the four: the escape
interpreters, the CRTC painters, the speech chips and the symbol parsers
held under ASan/UBSan fuzzing. What came back is state that outlives what it
should, and host-side bookkeeping.

## Verified, deferred

- **Step Out on an RTS-dispatch after a pop** (`Debugger.cpp`, `after >
  stepStartSp_`): stopped after a `PHA`, a routine that later does `PLA`
  then `PHA PHA RTS` as a jump is taken for the return. Needs the lowest SP
  since the candidate level tracked; low severity.
- **Hostile PostScript, CPU**: 16 queued jobs of `{} loop` are ~340 s of a
  pegged core from ~250 guest bytes. Needs a policy (drop the queue after a
  timeout?), not a constant.
- **Two POM2s on one print history**: the open-time sweep can delete a
  PNG the other instance is still encoding, and merge → pick a number →
  write is not atomic across processes. Needs `O_EXCL` names or a directory
  lock.
- **Printer memory bounded by count, not bytes**: 32 sheets is ~62 MB at
  Letter/144 but ~2 GB with 10"×69" custom paper at 300 dpi; and the
  Printer panel rebuilds up to 4 MiB of spool text under `stateMutex` every
  frame while open.
- **`takesMonitor` × 2 at the display**: `Apple2Display` still consults one
  card for `ownsScreen` / text colours; the second is only reachable in the
  Card Monitor.

## Checked and clean

CRTC R0-R17 at their extremes against every painter's clamps, Videx window
and bank indices, the VidHD's SCB / palette / pixel reach, TMS9918 VRAM
masks and sprite writers, the Chat Mauve painters' guard cells and its
snapshot v1-v5 checks; all card painting under `stateMutex`. SSI263 phoneme
and duration maths, the formant synthesiser's divisors, the TMS5220 FIFO and
tables, the MEA8000 buffer, `Dac8Audio`'s queue, the cassette's `.aci` / WAV
loaders and recording caps. The C. Itoh, ESC/P and Diablo 630 interpreters
(~1,100 hostile streams, all twelve models, both pacing paths), every card
spool's cap and cursor, the Ghostscript argv (`-dSAFER`, no shell, escaped
output name), history file names and atomic writes. Every OS-call-trace read
of guest memory is side-effect free and capped; the BASIC listings walk
bytes, not links; symbol and `.p2map` parsers under 20 000 fuzz inputs;
`CorpusManifest`, `WozRecover`, `DiskBuilder` bounds.

## Round 2 — the paint editor, accelerators and RAM cards, how firmware arrives, every card's lifecycle

Four more read-only reviewers: the HGR/DHGR paint and sprite editors with
the host exchange they use, the accelerators / clock chips / memory cards,
the ROM fetch-import-load path with every file in `roms/` as hostile, and a
sweep of the three bug classes round 1 found (power-off taken for RESET, no
time-jump handling, no side-effect-free ROM view) over every card it had not
touched. No memory-safety defect: both editors and the image converters held
under ASan/UBSan (6000 random operations, sources from 1×1 to 2000×2000),
the zip reader's bounds are by subtraction, every card loader checks its
size. The time-jump class came back clean bar one card.

### Fixed

| Area | Finding | Pin |
|---|---|---|

### Verified, deferred

- **A TransWarp and a socket accelerator together.** When the TransWarp is
  slow (`$C074`=1, a slot window) the Zip Chip's multiplier takes over, and
  with both fast the stock-time mapping divides twice. Needs: the bus to say
  "an accelerator card holds the CPU" so `activeAccel()` stands down — or
  Slot Config to refuse the pair.
- **Probe order takes the first file that exists, not the first that
  loads.** A 0-byte `apple2e.rom` puts the machine in //e mode and never
  falls back to a valid `apple2p.rom`; same for the //c's 32 KB / 16 KB pair
  and the CFFA's two dumps. Needs: the candidate loop the Grappler+ and SSC
  loaders already have, in `MainWindow`'s startup and `ProfileSwitch`.
- **"Reload ROM" after the first-launch download** reloads the ][+ main ROM
  only; the next launch is a //e with the full slot map. The summary already
  says "pick a machine or restart". Needs: `applyProfile` on that path.
- **The host `unzip` / `tar` fallback** is reachable by a member the archive
  flags encrypted or with another method; its output is not size-capped
  while it runs (SHA gate and scratch removal still hold), and the `tar`
  branch does not flatten paths so it cannot succeed. Every archive served is
  stored or deflate: dropping the fallback is the likely answer.
- **Card ROM loaders read whole files before checking the size** (CCS 7710,
  DAN ][, Applicard, UltraTerm), under `stateMutex`; the Liron and the
  Workstation Card take the head of an oversized file.
- **Paint Save through the native dialog** can replace `PIC#062000` when the
  user typed `PIC` and confirmed that name; the sprite editor's browser Save
  has no overwrite prompt. A Load still clears the undo history.
- **Sprite canvas in the browser build**: one quad per pixel in one draw
  list passes ImGui's 16-bit index limit past ~16 000 pixels (WebGL2 has no
  vertex offset). Not run.
- **Hard reset** still leaves the Disk II's IWM mode shadow, while it resets
  the IWM; RamWorks' modulo aliasing of unpopulated banks is uncited [E].

### Checked and clean

Zip Chip unlock, reset and snapshot bounds; socket seating and mutual
exclusion; the clock fan-out to every audio source and slot; TransWarp
snapshot validation; Slinky and RamWorks indices; ThunderClock shift, DST
repeated hour, leap day, IRQ after restore. Every `roms/` write behind its
SHA-256 gate, `.part` + atomic replace, the shared curl argv (`-g`, https
only), the fetch worker's locking, the once-only first-launch offer,
character ROM sizes. IRQ / NMI across reset, unplug and restore on every
card; the coverage table of 42 cards × three lifecycle classes is in the
reviewer's report and came back with the eight items above.
